Step 2 · Chunking

Break documents into useful pieces

Chunking splits long text into smaller passages. Good chunk boundaries help retrieval return focused information without losing too much context.

Text → chunks
Why overlap?
A little overlap can preserve context when a sentence or idea falls near a chunk boundary. Too much overlap can add duplication and storage cost.

Step 3 · Embedding

Turn meaning into searchable numbers

An embedding model maps text to a vector: a list of numbers that represents aspects of its meaning. Similar meanings tend to be closer in vector space.

Chunks → vectors
Important simplification: these are illustrative, browser-generated vectors based on word categories—not real AI embeddings. Real systems use a trained embedding model.

Step 4 · Indexing

Build a searchable knowledge base

A vector store keeps vectors and usually the associated text, source, and metadata. An index helps the system find likely matches efficiently.

Vectors + text + metadata
What is stored?Concept

Each record connects an embedding to its original text and useful metadata. The embedding helps find similar content; the original text is what can be passed to the LLM.

Step 5 · Retrieval

Find the passages that best match

At query time, the question is represented for search. The system scores candidate chunks and selects relevant passages to use as context.

Question → relevant chunks
More chunks can add context, but irrelevant chunks can distract the model.
A simple keyword-overlap score. Production RAG may use vector similarity, keyword search, hybrid search, filters, and reranking.
